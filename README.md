# Demostración: GitHub Projects + Toggl Track

Repositorio mínimo para practicar el seguimiento de **un issue real** con GitHub Projects v2 y Toggl Track.

## Idea que se demostrará

- El **issue** vive en el repositorio y tiene número y URL.
- El **Project** contiene ese issue como tarjeta y organiza su estado.
- El **proyecto de Toggl** agrupa registros de tiempo; es un objeto distinto del Project.
- La extensión de Toggl puede iniciar el temporizador desde el issue. No sincroniza automáticamente el estado del Project ni sus campos.

## Guía

Consulta [`docs/paso-a-paso.md`](docs/paso-a-paso.md). El recorrido tiene un plan B manual, porque la extensión puede no mostrar el botón en todos los navegadores o perfiles.

## Para repetir la práctica

1. Abre el [issue #1](https://github.com/IES-Rafael-Alberti/demo-toggl-github-projects/issues/1).
2. Abre el [GitHub Project](https://github.com/orgs/IES-Rafael-Alberti/projects/272); comprueba que la tarjeta corresponde al issue y no a un borrador.
3. Vuelve al issue desde el repositorio y registra una sesión breve en Toggl.
4. Verifica el registro en Toggl y el estado de la tarjeta por separado.

No añadas claves, datos personales ni credenciales a este repositorio. Usa una cuenta propia de Toggl y detén el temporizador al terminar la demostración.
